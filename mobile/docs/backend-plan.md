# Следующий этап: реальные пользователи

Текущий редьюсер и AsyncStorage — только учебный клиент. Для настоящей многопользовательской работы нужен сервер: Supabase Auth, Postgres, Storage и Realtime либо аналогичный стек.

Основные сущности: profiles (одна запись человека), groups, group_members, join_requests, request_approvals (отдельное решение каждого участника), rooms, room_photos, conversations, conversation_members, messages, saved_groups, reports и blocks. Число мест в группе отделяется от количества спален и наличия жилья. Индивидуальная доля аренды хранится отдельно от общей стоимости квартиры.

Порядок подключения:

1. Регистрация и восстановление сессии. Профиль связан с идентификатором Auth; экран «Моя анкета» пишет только собственные поля. Участники групп приглашаются, а не добавляются как учебные персонажи.
2. Публичные карточки и фотографии жилья. Точные адреса и контактные данные не публикуются в общей выдаче. Фотографии загружаются через разрешённые пользовательские операции Storage.
3. Серверные запросы на вступление и согласия. Каждый отвечает только за себя. Чат создаётся серверной транзакцией после подтверждения текущего состава; при изменении состава старые подтверждения нужно пересмотреть. Финальное вступление повторно проверяет свободные места и состав в транзакции.
4. Доступ к сообщениям через membership и RLS. Проверки только в мобильном интерфейсе недостаточны. Отправлять и читать сообщения можно только в разрешённых беседах; повторные запросы не создают дублей.
5. Жалобы, блокировки и удаление аккаунта до пилота с реальными людьми. Закрытые комнаты, переписки и фотографии проверяются с несколькими тестовыми аккаунтами на отсутствие доступа у посторонних.

Supabase project URL и publishable key могут использоваться клиентом; service-role и другие серверные секреты никогда не попадают в приложение или публичные EXPO_PUBLIC-переменные. Значения предоставляются через настройки среды, не через чат. Сессии на устройстве нужно хранить подходящим защищённым способом; текущий AsyncStorage содержит только несекретные данные демо.

Подписанные сборки и публикация — отдельный этап через EAS и аккаунты разработчика Apple/Google. После проверки на устройствах выбираются окончательные bundle/package identifiers и настраиваются права приложения. Экспорт бандлов в этом репозитории публикацией не является.
